## 1. cambc version vs patch notes

```
python -m pip index versions cambc
cambc (3.0.5)
Available versions: 3.0.5, 3.0.4, 3.0.3, ...
pip download cambc --no-deps   ->  cambc-3.0.5-py3-none-win_amd64.whl   (py3-none: works on Python 3.13)
C --version                    ->  cambc 3.0.5
```

Evidence that 3.0.5 is patch102. A probe bot drafted Stellar, Heart of Ruin, Vesper Vale and
Vendetta, then printed `self().base_stats()` (`C run statprobe statprobe --map 00rows --rounds 3`):

```
STATS stellar       hp=650+65   str=30+3.5 focus=70+7      patch102: 650, 65, 70, 7            ✓
STATS heart_of_ruin hp=1000+100 str=30+3.5 focus=100+12    patch102: str 30, +3.5; patch101: +12 ✓
STATS vesper_vale   hp=1000+100 str=55+5   focus=100+10    patch102: 1000, 55                   ✓
STATS vendetta      hp=1000+100 str=70+6   focus=100+10    patch102: 1000; patch100: +6         ✓
```

SDK constants in `sdk/cpp/cambc.h`: `prism_focus_per_gem = 1.5f` (patch102),
`vesper_vale_bonus_gold_percent = 33` and `marcella_tribute_gold_per_gem = 2` (patch100);
`camp_type::golem` and `champion_draft::heart_of_ruin` exist (patch100).
Stats JSON: `engineVersion "1.0.3"`. **Matches. Pin `cambc==3.0.5`.**

## 5. Files a C++ bot needs to build

`tools/benchmark.py` copies only `bots/<bot>/src` into `<output>/inputs/<bot>/src`, outside
the workspace, and `run-batch` builds it there:

```
python tools/benchmark.py starter starter --maps 00rows 00lanes --jobs 4 --output <scratch>/bench1 \
  --json --no-progress --color never --runner .venv\Scripts\cambc.exe     (PYTHONUTF8=1)
-> 4 games, 0 errors, exit 0, 40 s including build
```

The build uses the workspace's `cmake/CMakeLists.txt` (`GLOB_RECURSE ${BOT_DIR}/src/*.cpp`),
`sdk/cpp` (include dir) and the toolchain in the user cache. **Bots: only sources (matches).**
The workspace-level `cmake/CMakeLists.txt` is a build input: it belongs in the manifest and
outside agent scope. `.h`/`.hpp` files in subdirectories would be picked up by the
recursive glob; §8 forbids subdirectories anyway. The CLI binary contains the string
`build scripts are forbidden`.

## 6. SDK headers

`sdk/cpp`: `cambc.h`, `imports.h` (included by `cambc.h`), `wasm_simd128.h`. The starter uses
**angle brackets**: `#include <cambc.h>`. Standard headers come from the wasi-sdk-33 sysroot
(`wasm32-wasip1/eh/c++/v1`, 191 entries including internal `__*` dirs). §8.3 assumed
`"cambc.h"`-style. Proposal below.

## 7. Bot faults

A bot that calls `__builtin_trap()` on every gameplay turn, vs `starter` on `00rows`:

```
{"side":"A","scores":{"teamA":0,"teamB":458},"rounds":2000,"faults":{"teamA":8000,"teamB":0},"error":"bot faults: ..."}
{"side":"B","scores":{"teamA":489,"teamB":0},"rounds":2000,"faults":{"teamA":0,"teamB":10000},...}
stats: "diagnostics": {"botFaults": {"teamA": 8000, "teamB": 0}, "codes": [], "detailedCaptureComplete": true}
```

The counts are per team and per faulting champion-turn (4 or 5 champions × 2000 rounds). **Matches.**
The game still finishes, and the faulting team scores 0.

A bot that fails to compile: `run-batch` exits 1, writes **no** stats or replay files, and
`runner.log` contains `error: cmake build failed` with the path `inputs/<bot>/...`, so the
failing bot can be identified from the log (relevant to open issue 12).

## 8. Determinism (PC part)

The same benchmark (`starter` vs `starter`, `00rows` + `00lanes`, both sides) ran twice:
outcome, gems, rounds **and replay sha256** identical in every game. The stats carry
`match.seed` (`7750678344809992228` for 00rows, `15497727643895809986` for 00lanes), the same
in both runs; it seems to come from the map, not the clock. The Actions part needs a workflow (open issue 19).

## 14. `run-batch` with prebuilt WASM

`run-batch --help`: `--jsonl <JSONL>  API v1 compiled-input JSONL manifest; stdout contains only
machine events`. The binary's strings mention `compiled input must be a file`, `maximum 128
matches per worker batch`, `replay output must end in .zip`, `invalid job ID`. The format is not
documented. **Prebuilt input is supported in principle; deferred** (optional, §17).

## 15. tools on Windows (Linux pending)

- `tools/benchmark.py`: works with `--runner .venv\Scripts\cambc.exe` and `PYTHONUTF8=1`
  (see items 5 and 7).
- `tools/tests/test_benchmark.py`: **5 of 6 fail**: `map directory not found: <repo>\maps`.
  The tests run `benchmark.py` in the real repo with bots `v10`/`v06` and map `rows`,
  which do not exist here. The fake runner is a shebang script (not runnable on Windows),
  and one test sends SIGINT. This will also fail on Linux after bootstrap (the map is `00rows`, no `v10`).
- `tools/replay.mjs`: fails on Windows (`spawnSync unzip`). It also maps only engine
  versions v0_0_1–v0_0_3, while 3.0.5 replays are **v1.0.3** (header bytes `01 00 03`), so it
  would throw `unknown engine version` on Linux too.

## 16. Asset paths

Windows cache: `%LOCALAPPDATA%\cambc\` (`assets/`, `wasi-sdk-33/`, `cmake-3.31.8-…`,
`ninja-1.12.1-…`), not `~/.cache/cambc`. `assets/` holds **five** hash directories from
earlier CLI versions (Oct 15–22). Only the newest (`2efb693d…`, created by 3.0.5) has
`visualiser/assets/v1_0_3-DRqNt1t2.wasm`. The hard-coded `27ebcf25…` directory does not exist,
and `mapgen.mjs` hard-codes the old `v0_0_3` map-editor WASM. The D8 glob fix must choose by
file: the newest `v<engine>-*.wasm` present across the asset directories. Linux path pending.
